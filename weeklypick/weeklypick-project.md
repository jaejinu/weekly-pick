## 1. 문서 목적과 우선순위

### 1.1 목적

이 문서는 위클리픽 모바일 MVP를 **화면 단위로 구현 가능하게** 정의한다. 기준 문서 `beginner-project.md`의 장 구성·항목·명세 수준·완료 기준을 유지하고, 내용은 위클리픽 기획으로 전면 재작성했다. 기존 서비스명을 치환한 문서가 아니다.

### 1.2 자료 우선순위

1. 접근성 기준 (대비, 터치 영역, 포커스, 대체 텍스트)
2. `weeklypick-design-rull.md`의 토큰과 컴포넌트 계약
3. 이 문서의 화면 명세
4. `weeklypick-plan.md`의 콘텐츠와 정책

충돌하면 위 순서가 높은 쪽을 따르고, 2.3 `충돌 항목 최종 결정`에 기록한다.

### 1.3 명칭 규칙

- 서비스명은 한글 `위클리픽`, 워드마크는 `WEEKLY PICK`을 사용한다.
- 화면 이름은 사용자가 보는 제목과 같게 쓴다. (`전시 탐색`, `내 주말`)
- 컴포넌트 이름은 디자인 문서 16.1의 이름을 그대로 쓴다.
- 전시 데이터의 id는 `ex-01` 형식, 기사 `art-01`, 후기 `rv-01`, 권역 `rg-jongno` 형식을 쓴다.

## 2. 기준 문서에서 유지·변형한 내용

### 2.1 `beginner-project.md`에서 유지하는 내용

- 8개 논리 화면을 기준으로 한 화면 구성 방식과 화면별 명세 항목
- 하단 내비게이션 + 상세 화면 StickyActionBar 구조
- 목록 → 상세 → 행동으로 이어지는 흐름 설계
- 검색·필터·정렬·결과 수·빈 결과 처리 방식
- 저장의 `localStorage` 동기화와 새로고침 복원
- 상태(빈·로딩·오류·완료)를 별도 페이지가 아니라 화면 내 상태로 구현하는 원칙
- 샘플 데이터임을 사용자에게 명시하는 안내
- 컴포넌트 계약, 이미지 구현 규칙, QA 체크리스트, MVP 완료 정의의 상세 수준

## 3. 서비스 정의와 핵심 메시지

### 3.1 한 줄 정의

이번 주말 갈 수 있는 서울의 전시·팝업만 골라, "왜 볼 만한지" 한 줄과 관람 팁을 붙여 **매주 목요일 발행**하는 큐레이션 매거진 모바일웹.

### 3.2 핵심 메시지

> 이번 주말, 갈 만한 것만.

### 3.3 서비스 성격

- **전시 정보 사이트가 아니다** — 나열하지 않고 고른다. 이번 호에 실리는 전시는 10개뿐이다.
- **예매 앱이 아니다** — 무료·팝업을 포함해 "갈 만한지"를 판단하게 한다. 결제하지 않는다.
- **주간 매거진이다** — 호수와 발행일이 있고 지난 호가 남는다.

### 3.4 제품 원칙

1. **고른 이유를 밝힌다.** 모든 전시에 에디터 한 줄이 붙는다. 이유 없는 추천을 하지 않는다.
2. **판단 정보를 같은 자리에 둔다.** 소요 시간 · 예약 · 요금이 카드와 상세에서 항상 같은 순서로 보인다.
3. **저장에서 끝내지 않는다.** 저장한 전시는 토·일 슬롯으로 이어지고, 다녀오면 후기로 닫힌다.
4. **끝난 것을 지우지 않는다.** 종료된 전시는 아래로 내려가되 남아서 아카이브가 된다.
5. **모르는 것을 아는 척하지 않는다.** 가상 데이터임을 숨기지 않고, 지도·예매는 외부로 넘긴다.

## 4. 핵심 사용자, 문제와 제공 가치

### 4.1 Primary User

- 서울 거주 20~30대
- 전시·팝업에 관심과 취향이 있지만, 인스타그램과 블로그를 뒤지다 지쳐 결국 안 가는 사람
- 주말 반나절에 2~3곳을 묶어 다니는 동선형 소비를 한다
- 무료·소규모 전시와 팝업에 거부감이 없다
- 예약이 필요한지, 얼마나 걸리는지를 먼저 확인하고 움직인다

### 4.2 핵심 사용자 문제

1. **정보가 흩어져 있다.** 기간·지역·무료 여부로 한 번에 거를 방법이 없어 탐색 자체가 일이 된다.
2. **볼 만한지 판단할 근거가 없다.** 소요 시간, 예약 필요 여부, 왜 지금 봐야 하는지가 안 보여서 저장만 하고 안 간다.
3. **저장이 계획으로 이어지지 않는다.** 저장 목록은 쌓이는데 토·일 하루 동선으로 묶을 수단이 없다.

### 4.3 제공 가치

| 문제 | 위클리픽의 해결 | 화면 |
|---|---|---|
| 정보가 흩어져 있다 | 이번 주말에 갈 수 있는 10개만 한 호에 담고, 권역·무료·태그로 한 화면에서 거른다 | 홈, 전시 탐색 |
| 판단 근거가 없다 | 소요 시간·예약·요금 스트립을 카드와 상세 첫 화면에 고정하고, 에디터 한 줄로 "왜 지금"을 붙인다 | 전시 상세 |
| 계획으로 안 이어진다 | 저장 즉시 토요일에 넣을 수 있고, 토·일 슬롯이 소요 시간 합계와 반나절 초과를 알려준다 | 저장 목록, 내 주말 |
| 다녀온 뒤가 없다 | 별점과 80자 후기로 닫고, 다음 사람의 판단 근거가 된다 | 후기 작성, 후기 피드 |

## 5. MVP 범위와 제외 범위

### 5.1 핵심 화면

전체 MVP는 **11개 논리 화면**과 공통 상태로 구성한다. 기준 문서의 8화면을 모두 승계하고 3개를 추가했다.

| # | 화면 | 경로 | 핵심 역할 | 하단 고정 UI |
|---:|---|---|---|---|
| 1 | 홈(이번 호) | `#/home` | 이번 호의 픽과 다음 행동 제시 | BottomNavigation (홈) |
| 2 | 전시 탐색 | `#/discover` | 검색·필터·정렬·결과 목록 | BottomNavigation (전시) |
| 3 | 전시 상세 | `#/exhibition/:id` | 판단 정보·에디터 한 줄·저장·후기 연결 | StickyActionBar |
| 4 | 큐레이션 기사 | `#/article/:id` | 주말 동선 가이드 → 계획 생성 | StickyActionBar |
| 5 | 후기 피드 | `#/reviews` | 다녀온 사람들의 기록 탐색 | BottomNavigation (활성 없음) |
| 6 | 후기 상세 | `#/review/:id` | 후기 하나와 해당 전시 연결 | BottomNavigation (활성 없음) |
| 7 | 후기 작성 | `#/review/new/:exhibitionId` | 별점·한 줄·방문 정보 입력 | StickyActionBar |
| 8 | 저장 목록 | `#/saved` | 저장한 전시 모아보기 → 계획 연결 | BottomNavigation (저장) |
| 9 | 내 주말 | `#/my` | 토·일 계획, 내 후기, 최근 본, 아카이브 진입 | BottomNavigation (내 주말) |
| 10 | 지역별 모아보기 | `#/regions` | 권역 소개와 동선 기준 탐색 | BottomNavigation (활성 없음) |
| 11 | 아카이브 | `#/archive` | 현재 호와 지난 호 | BottomNavigation (활성 없음) |

로딩, 빈 결과, 이미지 실패, 오류, 완료, Toast는 별도 페이지가 아니라 해당 화면의 상태로 구현한다.

### 5.2 구현하는 기능

- 하단 내비게이션 4탭 화면 전환과 해시 라우팅
- 이번 주 픽 Slider 수동 스크롤(Scroll Snap)
- 전시 검색 (전시명·장소·권역·태그 대상)
- 권역 FilterChip(전체 + 4개), 무료 Toggle, 태그 FilterChip(5개) 동시 적용
- 고정 정렬 규칙 (종료 임박 → 픽 → 나머지 → 종료)
- 필터 0건 처리 (마지막 조건 풀기 / 전체 초기화)
- 전시 상세 진입과 뒤로 가기, 최근 본 전시 기록
- 저장·저장 해제와 저장 Toast 내 `토요일에 넣기` 지름길
- 토·일 슬롯 배치·이동·해제, 요일별 관람 시간 합계, 4시간 초과 안내
- 큐레이션 기사 3건과 `이 코스로 계획 만들기`(3개 저장 + 슬롯 배치)
- 후기 목록 정렬(최신순·별점순), 후기 상세
- 후기 작성 (별점 1~5, 80자, 방문 요일, 웨이팅 여부) 과 완료 상태
- 권역별 모아보기와 탐색 화면 연결
- 아카이브 (현재 호 / 첫 호 안내)
- `localStorage` 상태 유지와 새로고침 복원, 파싱 실패 시 기본값 복구
- 빈 상태, 로딩 Skeleton, 오류 상태, 완료 상태, Toast
- 샘플 데이터 고지

### 5.3 구현하지 않는 기능

- 회원가입, 로그인, 서버 인증
- 실제 전시 데이터와 공식 이미지 (가상 전시 + 생성 이미지 사용)
- 실시간 지도, 길찾기, 현재 위치 (외부 지도 검색 링크로 대체)
- 예매·결제 연동
- 개인화 추천, 푸시 알림
- 에디터 관리 화면 (발행은 데이터 파일 편집)
- PC 전용 레이아웃
- 후기 이미지 업로드, 댓글, 신고
- 백엔드, 관리자 페이지, 사용자 권한

## 6. 정보구조와 하단 내비게이션

### 6.1 하단 내비게이션

| 순서 | 탭 | 경로 | 아이콘 | 역할 |
|---:|---|---|---|---|
| 1 | 홈 | `#/home` | `fa-house` | 이번 호와 서비스 허브 |
| 2 | 전시 | `#/discover` | `fa-compass` | 전시 검색과 필터 |
| 3 | 저장 | `#/saved` | `fa-bookmark` | 저장한 전시 모아보기 |
| 4 | 내 주말 | `#/my` | `fa-calendar-week` | 방문 계획과 내 기록 |

- 기준 규정의 4탭 기본값을 사용한다. 제품 예외를 두지 않는다.
- 폭 398px, 높이 85px, pill, 좌우 16px, safe area 포함.
- 활성 탭은 잉크 + 라벨 600 + 라벨 아래 4px 점 인디케이터, 비활성은 muted + 500 + 점 없음. 아이콘은 네 탭 모두 solid 고정.
- 하위 화면(후기 피드·후기 상세·지역별·아카이브)에서는 **어떤 탭도 활성화하지 않는다.**

### 6.2 상세 화면 규칙

- 전시 상세, 큐레이션 기사, 후기 작성은 BottomNavigation을 숨기고 StickyActionBar를 사용한다.
- 나머지 화면은 BottomNavigation을 사용하고 고정 CTA를 두지 않는다.
- 모든 하위 화면에 DetailHeader(뒤로 가기)를 제공한다.
- 브라우저 뒤로 가기와 화면 내 뒤로 가기가 같은 history를 사용한다.
- 전시 상세 진입 시 최근 본 전시에 기록한다(최대 6개, 중복 제거, 최신 우선).

### 6.3 화면 진입 경로

```text
홈 ─┬─ 이번 주 픽 카드 ──────────→ 전시 상세
    ├─ 기사 배너 ───────────────→ 큐레이션 기사
    ├─ 마감 임박 카드 ───────────→ 전시 상세
    ├─ 이번 호 전시 "전체보기" ──→ 전시 탐색
    ├─ 다녀온 사람들 "전체보기" ─→ 후기 피드
    └─ 권역 카드 ───────────────→ 지역별 모아보기

전시 탐색 ── 카드 ─────────────→ 전시 상세
전시 상세 ─┬─ 다녀온 사람들 카드 → 후기 상세
           ├─ 후기 남기기 ──────→ 후기 작성
           └─ 같은 권역 카드 ───→ 전시 상세
큐레이션 기사 ─ STOP 카드 ──────→ 전시 상세
저장 목록 ── 주말 계획 세우기 ──→ 내 주말
내 주말 ─┬─ 내 후기 "전체보기" ─→ 후기 피드
         ├─ 최근 본 카드 ───────→ 전시 상세
         └─ 아카이브 진입 ──────→ 아카이브
지역별 ── "이 권역 전체 보기" ──→ 전시 탐색(권역 필터 적용)
```

## 7. 핵심 사용자 흐름

### 7.1 주 흐름 — 고르고, 계획하고, 다녀온다

```text
홈(이번 호)
  → 이번 주 픽 카드 선택
  → 전시 상세에서 소요 시간·예약·요금·에디터 한 줄 확인
  → 저장
  → Toast의 "토요일에 넣기" 또는 저장 목록 → 주말 계획 세우기
  → 내 주말에서 토·일 슬롯 확인, 합계와 반나절 초과 안내 확인
  → (다녀온 뒤) 전시 상세 → 후기 남기기 → 완료
```

### 7.2 탐색 흐름

```text
전시 탭 → 검색어 입력 또는 권역·무료·태그 필터 선택
  → 결과 수 확인 → 카드 선택 → 전시 상세 → 저장
  → (0건이면) "'무료' 조건 풀기" 또는 "전체 초기화"
```

### 7.3 코스 흐름

```text
홈 기사 배너 → 큐레이션 기사 → STOP 3개와 동선·비용 확인
  → "이 코스로 계획 만들기" → 3개 저장 + 토요일 배치 → 내 주말
```

### 7.4 기록 흐름

```text
홈 "다녀온 사람들" 또는 내 주말 "내 후기"
  → 후기 피드 → 정렬 전환 → 후기 상세 → 해당 전시 상세 → 저장
```

### 7.5 아카이브 흐름

```text
내 주말 → 아카이브 → 현재 호 확인 → (지난 호 없음) 첫 호 안내 → 홈
```

### 9.2 전시 탐색

**화면 목적**
이번 호 전시 10개를 권역·무료·태그·검색어로 걸러 갈 곳을 좁힌다.

**진입 경로**
하단 탭 `전시`, 홈 `이번 호 전시` 전체보기, 홈 검색 아이콘, 지역별 모아보기의 `이 권역 전체 보기`

**섹션 순서**

1. 화면 제목 `전시 탐색`
2. 검색 입력 (`fa-magnifying-glass`)
3. 필터 1줄 — 권역 FilterChip 5개 (`전체`, `종로·북촌`, `성수·건대`, `한남·용산`, `홍대·연남`)
4. 필터 2줄 — `무료만 보기` Toggle + 태그 FilterChip 5개 (`미술`, `사진`, `디자인`, `팝업`, `체험`)
5. 결과 요약 줄 — 결과 수 + 정렬 안내
6. 전시 목록 (`Card/ExhibitionVertical` 목록형)
7. 0건 상태
8. `Navigation/BottomNav` (전시 활성)

검색과 필터 영역은 상단 sticky로 고정하고, 결과 수는 항상 보이게 한다.

**표시할 정보**
검색어, 선택된 권역·태그·무료 여부, 결과 수, 각 전시의 이미지·배지·전시명·장소·기간·핵심 정보 스트립

**실제 문구**

| 위치 | 문구 |
|---|---|
| 화면 제목 | `전시 탐색` |
| 검색 placeholder | `전시명, 장소, 동네로 찾기` |
| 무료 Toggle | `무료만 보기` |
| 결과 요약 | `전시 7곳 · 이번 주에 끝나는 순` |
| 검색 입력 전 안내 | `무엇부터 볼지 모르겠다면 이렇게 찾아보세요` + 추천 키워드 `무료`, `30분`, `성수`, `사진` |
| 0건 제목 | `이 조건에 맞는 전시가 없어요` |

| 종료 구분선 | `종료된 전시` |

**주요 컴포넌트**
`Chip/Filter`, `Control/Toggle`, `Card/ExhibitionVertical`, `Info/InfoStrip`, `Badge/Status`, `State/Empty`, `Navigation/BottomNav`

**정렬 규칙 (고정, 사용자 변경 없음)**

```text
1군 종료 임박 (D-N 오름차순)
2군 이번 주 픽 (픽 순서)
3군 나머지    (종료일 오름차순)
4군 종료됨    (종료일 내림차순, 항상 맨 아래)
```

**Primary CTA** — 전시 카드 선택
**Secondary CTA** — `전체 초기화`, 0건의 조건 풀기 버튼

**사용자의 행동**
검색어 입력·삭제 / 권역 칩 선택(단일) / 태그 칩 선택(복수) / 무료 Toggle / 저장 토글 / 카드 선택

**이동할 다음 화면** — 전시 상세

**기본 상태** — 필터 없음, 전시 9곳 + 종료 1곳. 결과 요약 `전시 10곳 · 이번 주에 끝나는 순`
**검색 입력 전 상태** — 검색창에 포커스가 들어가고 입력이 비어 있으면 추천 키워드 4개를 칩으로 보여준다.
**빈 상태(0건)** — 위 문구 + 버튼 2개. 마지막으로 선택한 칩 이름을 버튼에 넣는다. 자동으로 조건을 완화하지 않는다.
**로딩 상태** — 목록형 카드 3개 Skeleton.
**오류 상태** — `전시 목록을 불러오지 못했어요. 잠시 뒤 다시 시도해 주세요.` + `다시 시도`
**완료 상태** — 저장 Toast, 필터 초기화 시 결과 수 갱신

**저장 또는 변경되는 데이터** — `weeklypick.saved`. 필터 상태는 세션 메모리에만 두고 저장하지 않는다.

**카드뉴스형 섹션 명세**

| 항목 | 전시 목록 (`Card/ExhibitionVertical` 목록형) |
|---|---|
| 전달할 핵심 내용 | 전시 한 곳이 어떤 공간이고, 얼마나 걸리고, 예약이 필요한지 |
| 이미지 ID · 파일명 | `img-01`~`img-10` · `assets/images/ex-01…ex-10*.webp` |
| 이미지 연결 이유 | 각 이미지는 해당 전시의 실제 관람 공간(매체·재료·조도)을 담고 있어 전시명만으로 알 수 없는 분위기를 전달한다 |
| 이미지 위치 · 비율 | 좌측 132×165(4:5), 라운드 16px, 배지는 이미지 좌상단 |
| 제목 · 설명 최대 줄 수 | 전시명 2줄, 장소·기간 1줄, 스트립 1줄 |
| 카드 선택 시 행동 | 전시 상세로 이동. 종료된 전시는 오버레이 + `종료됨` 라벨, 저장 버튼 숨김 |

### 9.3 전시 상세

**화면 목적**
이 전시를 이번 주말에 갈지 결정하게 한다. 결정에 필요한 정보를 첫 화면에 모두 둔다.

**진입 경로**
홈 픽·마감 임박·전시 목록 카드, 전시 탐색 카드, 기사 STOP 카드, 후기 상세의 전시 카드, 저장 목록, 지역별 모아보기, 내 주말의 최근 본 전시

**섹션 순서**

1. `Navigation/DetailHeader` — 투명, 스크롤 시 흰 배경 전환. 좌 뒤로 가기 / 우 저장
2. 히어로 이미지 (394×394)
3. 배지 행 (최대 2개) + `D-N`(종료 임박일 때)
4. 전시명 H1 (Noto Serif KR 30px)
5. 장소 · 기간
6. **핵심 정보 스트립** — 소요 시간 · 예약 · 요금
7. **에디터 한 줄** (`Info/EditorNote`) — 섹션 제목 없이 스트립 바로 아래에 붙인다
8. 관람 팁 (`Info/TipList`)
9. 오시는 길 (`Info/DirectionCard`)
10. 다녀온 사람들 (이 전시 후기 2개 + 전체보기)
11. 같은 권역 전시 Slider
12. 샘플 고지
13. `Button/StickyActionBar` — `저장` + `후기 남기기`

**430×800 첫 화면 안에 6번 핵심 정보 스트립과 7번 에디터 한 줄까지 들어와야 한다.**
검증값(430px 기준): 스트립 631–687px, 에디터 한 줄 711–760px. 에디터 한 줄에 섹션 제목을 두면 830px로 밀려 기준을 벗어난다.

**표시할 정보**
전시명, 장소, 주소, 기간, 요금, 예약 필요 여부, 소요 시간, 태그, 에디터 한 줄, 관람 팁 2~3개, 같은 권역 전시, 이 전시 후기 수와 평균 별점

**실제 문구**

| 위치 | 문구 |
|---|---|
| D-N 라벨 | `종료까지` + Anton `3` + `일` |
| 스트립 라벨 | `소요` / `예약` / `요금` |
| 에디터 한 줄 | 섹션 제목을 두지 않는다. 서명이 출처를 대신한다 |
| 에디터 서명 | `위클리픽 에디터` |
| 팁 섹션 | `가기 전에 알아두면 좋아요` |
| 오시는 길 섹션 | `오시는 길` |
| 지도 버튼 | `지도 앱에서 열기` (새 창으로 열립니다) |
| 후기 섹션 | `다녀온 사람들` / 더보기 `후기 전체보기` |
| 후기 없음 | `아직 이 전시 후기가 없어요. 다녀오셨다면 첫 줄을 남겨 주세요.` |
| 같은 권역 섹션 | `같은 동네 전시` |
| 종료 안내 | `이 전시는 9월 7일에 끝났어요. 후기는 남길 수 있어요.` |
| 샘플 고지 | `가상의 전시와 장소로 만든 샘플 콘텐츠입니다.` |
| StickyActionBar | `저장` / `저장됨` · `후기 남기기` |

**주요 컴포넌트**
`Navigation/DetailHeader`, `Badge/Status`, `Info/InfoStrip`, `Info/EditorNote`, `Info/TipList`, `Info/DirectionCard`, `Card/ReviewFeed`, `Card/ExhibitionVertical`, `Button/StickyActionBar`

**Primary CTA** — `저장` (저장됨 상태에서는 `저장됨` + solid 아이콘)
**Secondary CTA** — `후기 남기기`, `지도 앱에서 열기`, `후기 전체보기`

**사용자의 행동**
저장 토글 / 후기 남기기 / 지도 링크 열기 / 후기 카드 선택 / 같은 권역 카드 선택 / 뒤로 가기

**이동할 다음 화면** — 후기 작성, 후기 상세, 후기 피드, 다른 전시 상세, 외부 지도(새 창)

**기본 상태** — 저장 안 됨. StickyActionBar 좌측 `저장`(Outline), 우측 `후기 남기기`(Primary)
**저장됨 상태** — 좌측 버튼이 `저장됨` + solid 북마크 + 잉크 면. 다시 누르면 해제되고 Toast에 `되돌리기` 제공
**종료 임박 상태** — 배지 `종료 임박` + 상단에 `종료까지 3일` 표기. D-N은 Anton, 색은 `--color-accent-text`, 아이콘 `fa-hourglass-half` 병행
**종료됨 상태** — 히어로 이미지에 40% 오버레이 + `종료됨` 라벨. 종료 안내 문구 노출. **저장 버튼 비활성(숨김)**, `후기 남기기`만 전체 폭 사용
**빈 상태** — 후기 0개일 때 후기 섹션에 위 문구 + `후기 남기기` 버튼
**로딩 상태** — 히어로 Skeleton + 텍스트 3줄 Skeleton
**오류 상태** — 존재하지 않는 id면 `찾는 전시가 없어요. 이번 호 목록에서 다시 골라 주세요.` + `이번 호 보기`
**완료 상태** — 저장 Toast `저장했어요` + `토요일에 넣기`

**저장 또는 변경되는 데이터** — `weeklypick.saved`, `weeklypick.recent`(진입 시 기록), `weeklypick.plan`(Toast 액션)

**카드뉴스형 섹션 명세**

| 항목 | 히어로 이미지 |
|---|---|
| 전달할 핵심 내용 | 이 전시가 어떤 공간에서 열리는지 |
| 이미지 ID · 파일명 | 전시별 `img-01`~`img-10` |
| 이미지 연결 이유 | 전시명·장소만으로는 조도와 규모를 알 수 없다. 이미지가 "2시간짜리인지 30분짜리인지"의 감을 준다 |
| 이미지 위치 · 비율 | 화면 상단 full-bleed 394×394(1:1 크롭), `object-position: center 40%` |
| 제목 · 설명 최대 줄 수 | 전시명 H1 3줄, 장소·기간 1줄 |
| 카드 선택 시 행동 | 없음(이미지 자체는 링크가 아니다) |

| 항목 | 같은 동네 전시 Slider |
|---|---|
| 전달할 핵심 내용 | 이 전시와 묶어서 볼 수 있는 같은 권역의 다른 전시 |
| 이미지 ID · 파일명 | 같은 권역 전시들의 이미지 |
| 이미지 연결 이유 | 동선을 묶는 판단이므로 각 전시의 공간을 보여줘야 비교가 된다 |
| 이미지 위치 · 비율 | 카드 상단 4:5, 카드 폭 186px |
| 제목 · 설명 최대 줄 수 | 전시명 2줄, 장소·기간 1줄 |
| 카드 선택 시 행동 | 해당 전시 상세로 이동 |

### 9.4 큐레이션 기사

**화면 목적**
따로 있는 전시 세 곳을 하루 코스로 묶어 보여주고, 그 코스를 그대로 계획으로 만들게 한다.

**진입 경로**
홈 기사 배너, 기사 하단 `다른 코스` 카드, 아카이브

**섹션 순서**

1. `Navigation/DetailHeader` — 기사
2. `Card/ArticleOverlay` — 기사 헤드 (394×280)
3. 부제와 본문 (약 900자, 3~4문단)
4. STOP 카드 3개 (`Card/StopHorizontal`) + 사이의 이동 안내
5. 동선·비용 요약 (`Card/Plain`)
6. 다른 코스 2건 (`Card/StopHorizontal`)
7. 샘플 고지
8. `Button/StickyActionBar` — `이 코스로 계획 만들기`

**표시할 정보**
기사 제목, 부제, 본문, 정차점 3곳(시각·요금·소요 시간), 정차점 사이 이동 수단과 시간, 관람 시간 합계, 이동 시간 합계, 비용 합계

**실제 문구**

| 위치 | 문구 |
|---|---|
| 헤드 카테고리 | `이번 주 코스` |
| art-01 제목 | `3만 원으로 채우는 토요일 — 한남·성수 동선` |
| art-01 부제 | `빛의 방에서 종이 공방까지, 걸어서 이어지는 세 곳` |
| STOP 라벨 | `첫 번째` / `두 번째` / `세 번째` |
| 이동 안내 | `버스와 도보로 25분` |
| 요약 제목 | `이 코스 한눈에` |
| 요약 항목 | `관람 2시간 45분` · `이동 40분` · `비용 18,000원` |
| 요약 주석 | `관람 시간과 이동 시간은 따로 셌어요.` |
| 다른 코스 섹션 | `다른 코스도 있어요` |
| StickyActionBar | `이 코스로 계획 만들기` |
| 완료 Toast | `세 곳을 저장하고 토요일에 넣었어요` + `내 주말 보기` |

**주요 컴포넌트**
`Navigation/DetailHeader`, `Card/ArticleOverlay`, `Card/StopHorizontal`, `Card/Plain`, `Button/StickyActionBar`

**Primary CTA** — `이 코스로 계획 만들기`
**Secondary CTA** — STOP 카드(전시 상세), 다른 코스 카드

**사용자의 행동**
본문 읽기 / STOP 카드 선택 / 코스로 계획 만들기 / 다른 코스 선택

**이동할 다음 화면** — 전시 상세, 다른 큐레이션 기사, 내 주말(완료 Toast의 액션)

**기본 상태** — 코스 3개 정차점 표시, StickyActionBar 활성
**완료 상태** — `이 코스로 계획 만들기`를 누르면 3개 전시가 저장되고 토요일 슬롯에 순서대로 배치된다. 버튼이 `계획에 넣었어요`로 바뀌고 비활성화된다. Toast + `내 주말 보기` 액션.
**중복 처리** — 이미 저장·배치된 전시는 다시 추가하지 않고 건너뛴다. 토요일 합계가 4시간을 넘으면 배치는 하되 내 주말에서 초과 안내를 표시한다.
**빈 상태** — 해당 없음(기사에는 항상 정차점 2개 이상이 있다)
**로딩 상태** — 헤드 Skeleton + 본문 3줄 Skeleton
**오류 상태** — 없는 기사 id면 `찾는 코스가 없어요.` + `이번 호 보기`
**저장 또는 변경되는 데이터** — `weeklypick.saved`, `weeklypick.plan`

**카드뉴스형 섹션 명세**

| 항목 | 기사 헤드 (`Card/ArticleOverlay`) |
|---|---|
| 전달할 핵심 내용 | 이 코스의 첫인상과 성격(예산·동네·분량) |
| 이미지 ID · 파일명 | art-01 `img-01` / art-02 `img-06` / art-03 `img-03` |
| 이미지 연결 이유 | 각 코스의 첫 정차점 전시 이미지를 쓴다. 코스와 무관한 장식 이미지를 쓰지 않는다 |
| 이미지 위치 · 비율 | 카드 전체 배경 394×280, `object-position: center 45%`, 하단 60% Scrim |
| 제목 · 설명 최대 줄 수 | 제목 2줄, 부제 2줄 |
| 카드 선택 시 행동 | 없음(현재 화면의 헤드) |

| 항목 | STOP 카드 (`Card/StopHorizontal` ×3) |
|---|---|
| 전달할 핵심 내용 | 몇 시에 어디를 얼마에 보는지 |
| 이미지 ID · 파일명 | 해당 정차점 전시의 이미지 |
| 이미지 연결 이유 | 정차점이 곧 전시이므로 같은 대상의 이미지다 |
| 이미지 위치 · 비율 | 좌측 78×78(1:1 크롭), 라운드 12px |
| 제목 · 설명 최대 줄 수 | 라벨 1줄, 전시명 1줄, 시각·요금 1줄 |
| 카드 선택 시 행동 | 해당 전시 상세로 이동 |

동선·비용 요약은 이미지를 쓰지 않는 `Card/Plain` 유형이다.

### 9.5 후기 피드

**화면 목적**
다녀온 사람들의 기록을 모아 보여주고, 아직 안 본 전시를 고르는 또 하나의 근거를 준다.

**진입 경로**
홈 `다녀온 사람들` 전체보기, 내 주말 `내 후기` 전체보기, 전시 상세 `후기 전체보기`

**섹션 순서**

1. `Navigation/DetailHeader` — `다녀온 사람들`
2. 정렬 탭 — `최신순` / `별점순`
3. 후기 목록 (`Card/ReviewFeed`)
4. 빈 상태
5. 샘플 고지
6. `Navigation/BottomNav` (활성 탭 없음)

**표시할 정보**
후기 수, 정렬 기준, 각 후기의 전시 썸네일·전시명·별점·한 줄·방문 요일·웨이팅 여부

**실제 문구**

| 위치 | 문구 |
|---|---|
| 화면 제목 | `다녀온 사람들` |
| 정렬 탭 | `최신순` / `별점순` |
| 결과 요약 | `후기 6개` |
| 메타 예시 | `토요일 방문 · 웨이팅 없음` |

### 9.6 후기 상세

**화면 목적**
후기 하나를 온전히 보여주고, 그 전시로 이어지게 한다.

**진입 경로**
후기 피드 카드, 홈 다녀온 사람들 카드, 전시 상세의 후기 카드

**섹션 순서**

1. `Navigation/DetailHeader` — `후기`
2. 전시 카드 (`Card/StopHorizontal` 형태, 전시 상세로 연결)
3. 별점 + 방문 정보
4. 후기 본문(한 줄)
5. 이 전시의 다른 후기
6. 샘플 고지
7. `Navigation/BottomNav` (활성 탭 없음)

**표시할 정보**
대상 전시(썸네일·전시명·장소), 별점(아이콘 + 숫자), 후기 한 줄, 방문 요일, 웨이팅 여부, 작성 시점, 같은 전시의 다른 후기

**실제 문구**

| 위치 | 문구 |
|---|---|
| 화면 제목 | `후기` |
| 전시 카드 라벨 | `이 전시를 다녀왔어요` |
| 방문 정보 | `토요일 방문 · 웨이팅 없음` |
| 다른 후기 섹션 | `이 전시의 다른 후기` |
| 다른 후기 없음 | `이 전시 후기는 아직 하나예요. 다녀오셨다면 한 줄 더해 주세요.` |
| 다른 후기 없음 CTA | `후기 남기기` |

**주요 컴포넌트**
`Navigation/DetailHeader`, `Card/StopHorizontal`, `Review/RatingInput`(읽기 모드), `Card/ReviewFeed`, `State/Empty`, `Navigation/BottomNav`

**Primary CTA** — 전시 카드 선택(전시 상세)
**Secondary CTA** — `후기 남기기`, 다른 후기 카드

**사용자의 행동** — 전시 카드 선택 / 다른 후기 선택 / 후기 남기기 / 뒤로 가기
**이동할 다음 화면** — 전시 상세, 다른 후기 상세, 후기 작성

**기본 상태** — 후기 1건 + 같은 전시 다른 후기 목록
**빈 상태** — 같은 전시 후기가 이 하나뿐이면 위 안내 + `후기 남기기`
**로딩 상태** — 카드 1개 + 텍스트 2줄 Skeleton
**오류 상태** — 없는 후기 id면 `찾는 후기가 없어요.` + `후기 전체보기`
**완료 상태** — 해당 없음
**저장 또는 변경되는 데이터** — 없음

**카드뉴스형 섹션 명세**

| 항목 | 전시 카드 |
|---|---|
| 전달할 핵심 내용 | 이 후기가 어떤 전시에 대한 것인지 |

| 이미지 연결 이유 | 후기와 전시를 시각적으로 잇는다 |
| 이미지 위치 · 비율 | 좌측 78×78(1:1), 라운드 12px |
| 제목 · 설명 최대 줄 수 | 전시명 1줄, 장소·기간 1줄 |
| 카드 선택 시 행동 | 전시 상세로 이동 |

### 9.7 후기 작성

**화면 목적**
다녀온 사실을 30초 안에 기록하게 한다. 길게 쓰게 하지 않는다.

**진입 경로**
전시 상세 StickyActionBar `후기 남기기`, 후기 상세의 `후기 남기기`, 내 주말 `내 후기` 빈 상태

**섹션 순서**

1. `Navigation/DetailHeader` — `후기 남기기`
2. 대상 전시 확인 카드
3. 별점 입력 (`Review/RatingInput`, 1~5)
4. 한 줄 입력 (최대 80자, 글자 수 표시)
5. 방문 정보 — 요일 선택(토/일/평일), 웨이팅 여부(있음/없음)
6. 안내 문구
7. `Button/StickyActionBar` — `후기 등록`

**표시할 정보**
대상 전시명·장소, 선택한 별점, 입력한 글자 수/80, 방문 요일, 웨이팅 여부

**실제 문구**

| 위치 | 문구 |
|---|---|
| 화면 제목 | `후기 남기기` |
| 전시 확인 라벨 | `이 전시를 다녀오셨나요?` |
| 별점 라벨 | `얼마나 좋았나요?` |
| 별점 보조 | `별을 눌러 점수를 골라 주세요` |
| 한 줄 라벨 | `한 줄로 남겨 주세요` |
| 한 줄 placeholder | `40분이면 충분했어요, 오전이 한산해요` |
| 글자 수 | `0 / 80` |
| 요일 라벨 | `언제 다녀오셨나요?` |
| 요일 선택지 | `토요일` / `일요일` / `평일` |
| 웨이팅 라벨 | `웨이팅이 있었나요?` |
| 웨이팅 선택지 | `있었어요` / `없었어요` |
| 안내 | `후기는 이 브라우저에만 저장돼요.` |
| 등록 버튼 | `후기 등록` |
| 비활성 안내 | `별점과 한 줄을 채우면 등록할 수 있어요` |
| 완료 제목 | `고마워요. 다음 호에 반영할게요` |
| 완료 설명 | `남겨 주신 한 줄은 다른 사람이 고를 때 근거가 돼요.` |
| 완료 CTA 1 | `내 후기 보기` |
| 완료 CTA 2 | `전시로 돌아가기` |
| 오류 문구 | `한 줄은 80자까지 쓸 수 있어요. 지금 84자예요.` |

**주요 컴포넌트**
`Navigation/DetailHeader`, `Card/StopHorizontal`, `Review/RatingInput`, 텍스트 입력, `Chip/Filter`(요일·웨이팅), `Button/StickyActionBar`, `Overlay/ConfirmModal`(이탈 확인)

**Primary CTA** — `후기 등록`
**Secondary CTA** — 뒤로 가기

**사용자의 행동** — 별점 선택 / 한 줄 입력 / 요일 선택 / 웨이팅 선택 / 등록 / 취소
**이동할 다음 화면** — 완료 상태 → 후기 피드 또는 전시 상세

**기본 상태** — 별점 0, 입력 비어 있음, **등록 버튼 비활성**. 비활성 안내 문구를 버튼 위에 표시한다.
**입력 중 상태** — 별점 ≥ 1 이고 한 줄이 1자 이상이면 버튼 활성. 글자 수가 실시간으로 갱신되고 70자부터 색을 `--color-accent-text`로 바꾸고 숫자를 함께 표시한다.
**완료 상태** — 화면 전체를 완료 상태로 전환한다. 아이콘 + 완료 제목 + 설명 + CTA 2개. 뒤로 가기로 입력 화면에 돌아가지 않는다.
**빈 상태** — 해당 없음
**로딩 상태** — 등록 중 버튼 Loading(폭 유지), 중복 제출 차단
**오류 상태** — 80자 초과 시 입력 아래 오류 문구 + 입력 테두리 `--color-accent-text`. 등록 실패 시 `후기를 저장하지 못했어요. 다시 시도해 주세요.` + `다시 시도`
**이탈 처리** — 입력 중 뒤로 가기를 누르면 `쓰던 후기가 사라져요. 그만 쓸까요?` Modal. Primary `계속 쓰기`, Secondary `그만두기`

**저장 또는 변경되는 데이터** — `weeklypick.reviews`

**카드뉴스형 섹션 명세**

| 항목 | 대상 전시 확인 카드 |
|---|---|
| 전달할 핵심 내용 | 지금 후기를 쓰는 대상이 맞는지 확인 |
| 이미지 ID · 파일명 | 대상 전시의 이미지 |
| 이미지 연결 이유 | 전시명만 보여주면 다른 전시와 혼동할 수 있다 |
| 이미지 위치 · 비율 | 좌측 78×78(1:1), 라운드 12px |
| 제목 · 설명 최대 줄 수 | 전시명 1줄, 장소·기간 1줄 |
| 카드 선택 시 행동 | 없음(확인용, 링크 아님) |

별점·입력·선택 영역은 이미지를 쓰지 않는 `Card/Plain` 유형이다.

### 9.8 저장 목록

**화면 목적**
저장한 전시를 모아 보여주고, 곧바로 주말 계획으로 넘긴다.

**진입 경로**
하단 탭 `저장`

**섹션 순서**

1. 화면 제목 `저장한 전시`
2. 요약 스트립 (`Card/Plain`) — 저장 수, 계획에 넣은 수
3. 저장 목록 (`Card/ExhibitionVertical` 목록형 + 삭제 버튼)
4. **인라인** Primary CTA `주말 계획 세우기`
5. 빈 상태
6. 샘플 고지
7. `Navigation/BottomNav` (저장 활성)

**BottomNavigation과 고정 CTA를 동시에 두지 않기 위해 CTA는 목록 아래 인라인으로 배치한다.**

**표시할 정보**
저장 수, 계획 배치 수, 각 전시의 이미지·배지·전시명·장소·기간·핵심 정보 스트립·배치 여부

**실제 문구**

| 위치 | 문구 |
|---|---|
| 화면 제목 | `저장한 전시` |
| 요약 스트립 | `저장 2곳 · 계획에 넣은 곳 1` |
| 배치 라벨 | `토요일에 있어요` / `아직 안 넣었어요` |
| 인라인 CTA | `주말 계획 세우기` |
| 삭제 버튼 이름 | `저장 해제` |
| 유지 안내 | `저장은 이 브라우저에서만 유지돼요.` |
| 빈 상태 제목 | `아직 저장한 전시가 없어요` |
| 빈 상태 설명 | `이번 호부터 골라볼까요?` |
| 빈 상태 CTA | `이번 호 보기` |
| 해제 Toast | `저장을 해제했어요` + `되돌리기` |

**주요 컴포넌트**
`Card/Plain`, `Card/ExhibitionVertical`, `Button/Primary`, `Button/Icon`, `State/Empty`, `State/Toast`, `Navigation/BottomNav`

**Primary CTA** — `주말 계획 세우기` (내 주말로 이동)
**Secondary CTA** — 저장 해제, 카드 선택

**사용자의 행동** — 카드 선택 / 저장 해제 / 해제 되돌리기 / 계획 세우기
**이동할 다음 화면** — 전시 상세, 내 주말

**기본 상태** — 저장 2곳(`ex-01` 토요일 배치, `ex-02` 미배치)
**빈 상태** — 위 문구 + `이번 호 보기`. 요약 스트립과 인라인 CTA는 숨긴다.
**로딩 상태** — 카드 2개 Skeleton
**오류 상태** — `localStorage` 파싱 실패 시 기본값으로 복구하고 `저장 목록을 복구했어요. 일부 항목이 사라졌을 수 있어요.` 안내를 한 번 표시한다.
**완료 상태** — 해제 Toast + `되돌리기`(5초 내 복구 가능)
**저장 또는 변경되는 데이터** — `weeklypick.saved`, 해제 시 `weeklypick.plan`에서도 함께 제거

**카드뉴스형 섹션 명세**

| 카드 선택 시 행동 | 전시 상세로 이동. 삭제 버튼은 카드 링크 밖 형제 요소 |

### 9.9 내 주말

**화면 목적**
저장한 전시를 토·일에 배치해 실행 가능한 반나절 계획으로 만든다.

**진입 경로**
하단 탭 `내 주말`, 저장 목록 `주말 계획 세우기`, 기사 완료 Toast `내 주말 보기`

**섹션 순서**

1. 화면 제목 `내 주말`
2. 요약 타일 3개 (`Stat/SummaryTile`) — 저장 / 계획 / 후기
3. 미배치 전시 (있을 때만)
4. 토요일 슬롯 (`Plan/DaySlot`)
5. 일요일 슬롯 (`Plan/DaySlot`)
6. 내 후기
7. 최근 본 전시 (`Card/StopHorizontal`)
8. 아카이브 진입
9. 서비스 안내와 샘플 고지
10. `Navigation/BottomNav` (내 주말 활성)

**표시할 정보**
저장 수·계획 수·후기 수, 미배치 전시 목록, 요일별 배치 전시와 관람 시간 합계, 4시간 초과 여부, 내 후기 목록, 최근 본 전시, 현재 호 정보

**실제 문구**

| 위치 | 문구 |
|---|---|
| 화면 제목 | `내 주말` |
| 요약 타일 라벨 | `저장` / `계획` / `후기` |
| 주말 안내 | `이번 주말 9.12 토 – 9.13 일` |
| 미배치 섹션 | `아직 안 넣은 전시` |
| 미배치 버튼 | `토요일에 넣기` / `일요일에 넣기` |
| 토요일 슬롯 | `토요일 9.12` |
| 일요일 슬롯 | `일요일 9.13` |
| 합계 라벨 | `관람 합계` |
| 이동 시간 주석 | `이동 시간은 따로 봐야 해요.` |
| 슬롯 빈 상태 | `이 날은 아직 비어 있어요` |
| 4시간 초과 | `반나절 넘어요. 하나는 다음 주로 미뤄도 돼요` |

## 12. 이미지 생성 계획

### 12.1 규칙

- `assets/images/`에 **정확히 10장**을 생성한다.
- 가상 전시 10개와 1:1로 대응한다. 기사 헤드와 후기 썸네일은 해당 전시 이미지를 재사용한다.

- 실내 전시 공간 중심, 한국 도심 맥락, 자연광 또는 전시 조명. 과장된 AI 스타일을 쓰지 않는다.

## 13. 실제 콘텐츠와 샘플 데이터

모든 전시·장소·후기는 **가상**이다. 실제 기관이나 전시로 오해하지 않도록 모든 화면 하단과 상세 하단에 샘플 고지를 둔다.

### 13.1 기준일 상수

```text
TODAY        = 2026-09-10   (Vol.01 발행일, 목요일)
WEEKEND_SAT  = 2026-09-12
WEEKEND_SUN  = 2026-09-13
NEXT_ISSUE   = 2026-09-17
ENDING_SOON  = 종료일 <= TODAY + 10일  → 2026-09-20 이하
CLOSED       = 종료일 <  TODAY
```

D-N, 종료 임박, 종료됨 판정은 실제 시각이 아니라 **이 상수로만** 계산한다. 언제 열어도 같은 결과가 나와야 한다.

## 14. 로컬 상태 구조

```text
weeklypick.saved     // { v: 1, data: ["ex-01", "ex-02"] }
weeklypick.plan      // { v: 1, data: { sat: ["ex-01"], sun: [] } }
weeklypick.reviews   // { v: 1, data: [{ id, exhibitionId, rating, text, day, waiting, createdAt }] }
weeklypick.recent    // { v: 1, data: ["ex-03", "ex-07"] }
```

- 모든 키에 버전 필드 `v`를 둔다.
- JSON 파싱 실패, 스키마 불일치, 존재하지 않는 전시 id가 섞인 경우 **안전한 기본값으로 복구**하고 사용자에게 1회 안내한다.
- 상태 변경 직후 UI와 `localStorage`가 같은 값을 가져야 한다.
- 저장 해제 시 `plan`의 토·일 배열에서도 함께 제거한다.
- `recent`는 최대 6개, 중복 제거, 최신 우선.
- 저장·계획·후기는 로그인 없이 이 브라우저에만 남는다는 사실을 저장 목록·내 주말·후기 작성 화면에서 문구로 알린다.

## 15. 인터랙션 규칙

### 15.1 저장

- 저장 버튼은 `button` + `aria-pressed`로 구현한다.
- 카드 전체 링크 안에 저장 버튼을 중첩하지 않는다. 형제 요소로 두고 `position: absolute`로 배치한다.
- 저장 시 Toast `저장했어요` + **`토요일에 넣기` 액션**. 이 액션을 누르면 `plan.sat`에 추가하고 Toast를 `토요일에 넣었어요`로 교체한다.
- 저장 해제 시 Toast + `되돌리기`(5초). 되돌리기는 `saved`와 `plan`을 함께 복원한다.
- 종료된 전시에는 저장 버튼을 노출하지 않는다.
- 빠른 연속 클릭으로 상태가 어긋나지 않게 한다.

### 15.2 검색과 필터

- 검색은 전시명, 장소명, 권역명, 태그를 대상으로 한다. 공백은 무시하고 부분 일치로 처리한다.
- 검색어와 필터는 **동시에** 적용한다.
- 권역은 단일 선택(`전체` 포함 5개), 태그는 복수 선택, 무료는 Toggle이다.
- 결과 수는 필터가 바뀔 때마다 즉시 갱신하고 `aria-live="polite"`로 알린다.
- 정렬은 고정 규칙이며 사용자가 바꾸지 않는다. 결과 요약에 `이번 주에 끝나는 순`으로 명시한다.
- 0건이면 자동으로 조건을 완화하지 않는다. 버튼 2개(`'{마지막 칩}' 조건 풀기`, `전체 초기화`)를 제공한다.
- 마지막으로 선택한 칩이 없으면(검색어만으로 0건이면) 첫 버튼을 `검색어 지우기`로 바꾼다.

### 15.3 방문 계획

- 배치·이동·제거는 모두 **버튼**으로 한다. 드래그를 쓰지 않는다.
- 요일별 합계는 배치된 전시의 `duration` 합이다. **이동 시간은 포함하지 않으며**, 합계 아래에 `이동 시간은 따로 봐야 해요.`를 항상 표시한다.
- 합계가 240분을 넘으면 안내를 표시한다. 배치를 막지 않는다.
- 같은 전시를 두 요일에 동시에 넣을 수 없다. 이동 시 기존 요일에서 제거한다.
- 계획에서 뺀 전시는 저장 목록에는 남는다.

### 15.4 기사 코스 적용

- `이 코스로 계획 만들기`는 정차점 전시를 순서대로 `saved`에 추가하고 `plan.sat`에 배치한다.
- 이미 저장·배치된 전시는 건너뛴다.
- 종료된 전시가 정차점에 있으면 배치하지 않고 건너뛴다(현재 데이터에는 없다).
- 적용 후 버튼은 `계획에 넣었어요`로 바뀌고 비활성화된다. 중복 실행을 막는다.

### 15.5 후기 작성

- 별점 미선택 또는 한 줄이 비어 있으면 등록 버튼을 비활성한다.
- 80자를 넘으면 입력을 막지 않고 오류 문구와 현재 글자 수를 보여준다. 등록 버튼은 비활성한다.
- 등록 중에는 버튼 Loading, 중복 제출 차단.
- 등록 후 화면 전체를 완료 상태로 전환하고 뒤로 가기로 입력 화면에 돌아가지 않게 한다.
- 입력 중 이탈 시 확인 Modal.

### 15.6 화면 전환

- 해시 라우팅(`#/home`, `#/exhibition/ex-01`)을 사용한다.
- 화면 전환 시 스크롤을 맨 위로 올린다. 뒤로 가기로 목록에 돌아올 때는 이전 스크롤 위치를 복원한다.
- 전환 애니메이션은 220–360ms, `prefers-reduced-motion`에서 제거한다.
- 데이터 오류가 내비게이션을 막지 않는다.

### 15.7 Slider

- CSS Scroll Snap, 간격 12px, 자동재생 없음.
- 터치 드래그와 키보드 좌우 이동을 지원한다.
- 마지막 카드 뒤에 빈 영역이 없어야 한다.
- Slider 컨테이너만 가로 스크롤되고 페이지 전체는 스크롤되지 않는다.
- `role="group"` + `aria-label`로 현재 목록의 성격과 개수를 전달한다.

## 16. 접근성과 안전

### 16.1 접근성

- 페이지당 H1 하나. 홈은 호 타이틀, 상세는 전시명이 H1이다. 제목 단계를 건너뛰지 않는다.
- 모든 인터랙션 요소가 키보드 포커스를 받고 Focus Ring이 보인다.
- 터치 영역 최소 44×44px, 인접 대상 사이 8px 이상.
- 본문 대비 4.5:1 이상, UI 경계 3:1 이상. 확정 대비값은 디자인 문서 15.1을 따른다.
- **상태를 색상만으로 표시하지 않는다.**
  - 배지 = 아이콘 + 텍스트
  - 활성 탭 = 라벨 굵기 + 점 인디케이터
  - 별점 = solid/regular + 숫자
  - 4시간 초과 = 아이콘 + 문장
  - 종료됨 = 오버레이 + `종료됨` 라벨 + 목록 최하단 배치
- 저장·배치·등록 결과는 `aria-live="polite"`로 알린다.
- Modal은 포커스 트랩과 포커스 복귀를 구현한다.
- 글자 확대 200%에서 홈 → 상세 → 저장 → 계획 배치를 완료할 수 있어야 한다.
- `prefers-reduced-motion`을 존중한다.
- 이미지에 구체적인 한국어 `alt`를 제공한다.

### 16.2 안전과 정직성

- 모든 전시·장소·후기가 **가상**임을 화면 하단과 상세 하단에 표기한다.
- 실제 기관명, 실제 전시명, 실제 작가명을 쓰지 않는다.
- 요금·기간·예약 정보를 실제 정보처럼 보이게 하지 않는다.
- 지도와 길찾기는 외부 지도 검색 링크로만 연결하고, 새 창으로 열림을 문구로 알린다.
- 저장·계획·후기가 이 브라우저에만 남는다는 한계를 숨기지 않는다.
- 없는 기능을 있는 것처럼 보이는 장식 버튼을 만들지 않는다.

## 17. 구현 원칙

### 17.1 구조

```text
weekly-pick/
├─ index.html
├─ css/
│  ├─ tokens.css
│  ├─ components.css
│  └─ app.css
├─ js/
│  ├─ data.js         // 호·전시·권역·기사·후기 데이터, 기준일 상수
│  ├─ state.js        // localStorage 읽기·쓰기·복구, 파생 계산(배지·정렬·합계)
│  ├─ components.js   // 카드·배지·스트립·상태 렌더 함수
│  └─ app.js          // 라우팅, 화면 렌더, 이벤트 위임
├─ assets/images/     // 생성 이미지 10장
└─ weeklypick/
   ├─ weeklypick-design-rull.md
   ├─ weeklypick-project.md
   └─ weeklypick-image-prompts.md
```

### 17.2 HTML

- 의미 있는 요소를 사용한다: `header`, `nav`, `main`, `section`, `article`, `ul`, `li`, `time`
- 링크 이동은 `a`, 상태 변경은 `button`. 클릭 가능한 `div`를 만들지 않는다.
- 카드 전체 링크 안에 링크나 버튼을 중첩하지 않는다.
- 기간과 발행일은 `time datetime="2026-09-12"` 형식을 쓴다.
- 이미지에 `width`/`height`를 지정해 Layout Shift를 줄인다.
- 아이콘만 있는 버튼에 `aria-label`을 제공한다.
- Font Awesome 아이콘은 `aria-hidden="true"`로 두고 의미는 텍스트로 전달한다.

### 17.3 CSS

- `tokens.css`에 디자인 문서의 토큰만 정의한다.
- 컴포넌트에 페이지 전용 값을 하드코딩하지 않는다.
- 텍스트 컨테이너에 불필요한 고정 높이를 쓰지 않는다.
- `100dvh`를 우선한다.
- 앱 셸 전체를 `overflow-x: auto`로 만들지 않는다. Slider 컨테이너에만 가로 스크롤을 둔다.
- `overflow: hidden`은 이미지가 있는 카드 내부에 한정한다.

### 17.4 JavaScript

- 화면·필터·저장·계획·후기가 하나의 상태 모델을 사용한다.
- 이벤트는 위임 방식으로 등록해 재렌더 후 중복 등록되지 않게 한다.
- 저장·배치·등록의 중복 제출을 차단한다.
- Slider 이동값을 카드 개수에 하드코딩하지 않는다.
- 날짜 판정은 `TODAY` 상수만 사용한다. `new Date()`로 현재 시각을 읽지 않는다.
- 이미지·데이터 오류가 내비게이션을 막지 않는다.
- 지도·예매처럼 실제 기능이 없는 부분은 실패한 척하지 않고 명시적인 외부 링크 또는 안내로 처리한다.

## 20. MVP 완료 정의

1. 11개 화면이 모두 구현되고 문서의 섹션 순서를 따른다.
2. 하단 4탭과 해시 라우팅이 동작한다.
3. 핵심 흐름을 브라우저에서 끝까지 실행할 수 있다.
   홈 → 전시 상세 → 저장 → (Toast 또는 저장 목록) → 내 주말 슬롯 배치 → 합계 확인 → 후기 작성 → 완료
4. 기사 흐름이 동작한다. 기사 → `이 코스로 계획 만들기` → 3개 저장 + 토요일 배치 → 내 주말.
5. 탐색의 검색·필터·정렬·0건 처리가 모두 동작한다.
6. 종료된 전시가 삭제되지 않고 규칙대로 표시된다.
7. `localStorage`가 새로고침 후 유지되고 손상 시 복구된다.
8. 이미지 10장이 생성되어 `assets/images/`에 있고 모두 화면에 적용됐다.
9. 카드뉴스형 콘텐츠마다 내용에 맞는 이미지가 있고, 텍스트만 든 사각 카드가 반복되지 않는다.
10. 모든 화면에 실제 한국어 문구가 있고 AI식 문구가 없다.
11. Font Awesome이 프로젝트 전체에 일관되게 적용됐다.
12. 승인된 3색과 무채색 파생 외의 색이 없다.
13. 빈 상태·로딩·오류·완료 상태가 구현됐다.
14. 360 / 390 / 430 / 431+ 에서 수평 스크롤과 레이아웃 깨짐이 없다.
15. 접근성 기준(터치 영역·대비·포커스·대체 텍스트·색상 외 상태 표시)을 만족한다.
16. 콘솔 오류가 없고 동작하지 않는 주요 버튼이 없다.
17. 최소 3회의 테스트·수정·회귀 테스트를 완료했다.
