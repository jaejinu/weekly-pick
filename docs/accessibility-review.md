# 접근성 점검 기록

최초 점검: 2026-10-05. 추가 Mac 점검: 2026-10-07. 대상: 화면 이동 접근성 보완 코드와 운영 사이트. 이 기록은 접근성 인증이나 실제 스크린리더 전체 흐름의 통과 결과가 아니다.

## 자동 검사

| 항목 | 방법 | 결과 |
|---|---|---|
| 화면 이동 | 홈에서 하단 저장 링크에 포커스 후 Enter, 목적 화면 h1 포커스 확인 | Chromium·WebKit 통과 |
| 화면 식별 | 화면별 document.title, 후기·동네·지난 호·계정·개인정보 h1 확인 | Chromium·WebKit 통과 |
| 검색 입력 | 검색 바로가기 포커스, 필드의 표시되는 외곽선 확인 | Chromium·WebKit 통과 |
| 기존 조작 | 별점 방향키, 확인창 포커스 순환·Escape, 필터·정렬·일정 조작 후 포커스 | Chromium·WebKit 통과 |
| 계정 회귀 | 실제 SDK + 모의 HTTP로 로그인 복귀·동의·오류·탈퇴 확인 흐름 | Chromium·WebKit 통과 |

검사 명령은 README의 검증 절을 따른다. 모의 계정 검사는 실제 메일 발송·실계정 삭제·실제 CAPTCHA 검증을 의미하지 않는다.

## 실제 Safari 관찰

계정 서버에 연결하지 않는 로컬 데모를 Safari에서 열었다. macOS 접근성 트리에서 다음을 확인했다.

- 페이지 제목: `Vol.01 — 9월 둘째 주 — 위클리픽`
- 대표 제목: `Vol.01 — 9월 둘째 주`, 머리말 레벨 1
- 저장 버튼: 전시명과 저장/저장 해제 이름, 토글 상태 0/1
- 하단 탐색: 홈·전시·저장·내 주말 링크

이후 Safari 창을 도구에서 찾지 못해 VoiceOver 실행 단축키가 전달되지 않았다. 창 복원 재시도도 `window_not_found`로 실패했다. VoiceOver를 켰거나 음성 출력·커서 이동을 검증했다고 주장하지 않는다. 자동 검사의 WebKit은 실제 Safari·VoiceOver 조합을 대체하지 않는다.

## 2026-10-07 Mac Safari 추가 점검

환경: macOS 27.0.1 (26A434), Safari 27.0.1. 대상: 운영 사이트 `https://weekly-pick.vercel.app`의 비로그인 화면. Orca의 macOS 접근성 트리와 UI 조작 후 재조회로 확인했다. 아래 결과는 실제 Safari 관찰이며 VoiceOver 음성 낭독 검증이나 실제 사용자 관찰 결과를 뜻하지 않는다.

| 항목 | 실제 관찰 | 판정 |
|---|---|---|
| 홈·전시 상세 | 대표 제목이 레벨 1로 노출되고 전시 카드의 저장 버튼에 전시명과 선택 상태 0/1이 표시됨 | 접근성 정보 확인 |
| 계정 → 저장 | 하단 저장 링크 실행 후 HTML 콘텐츠 제목이 `저장한 전시 — 위클리픽`으로 바뀌고 포커스가 `저장한 전시` 레벨 1 제목으로 이동 | 화면 이동·포커스 확인 |
| 저장 → 전시 | 전시 링크 실행 후 `전시 탐색` 레벨 1 제목으로 포커스 이동 | 화면 이동·포커스 확인 |
| 검색 | `전시 검색` 이름과 안내 문구 노출. 한글 문자열 `사진` 설정 후 재조회에서 전시 2곳과 `골목의 기록: 북촌 사진전`, `창밖 서울 — 사진 기획전` 확인 | 문자열 검색 확인. 실제 한글 IME 조합은 미검증 |
| 계정 화면 | `이메일 주소` 필드, `개인정보 수집·이용에 동의해요.` 체크상자, 개인정보 처리 안내 링크 노출. 로그인 링크 받기는 미입력 상태에서 비활성화 | 입력 이름·상태 확인 |
| VoiceOver | 초기 프로세스 없음 → 실행 프로세스 확인 → 종료 후 프로세스 없음 확인 | 실행·복원만 확인, 낭독·커서 이동 미검증 |

도구의 조작 직후 스냅샷에는 이전 창 제목이나 입력 값이 잠시 남았다. 검색어 설정은 `value_mismatch`로 보고되기도 했으므로, 명령 성공 여부만으로 판정하지 않고 이후 접근성 트리를 다시 읽어 결과를 확인했다. 합성 텍스트 입력과 접근성 값 설정은 실제 한글 키보드 조합을 대신하지 않는다.

VoiceOver 단축키 `Cmd+F5`는 도구에서 지원하지 않아 앱을 직접 실행했다. VoiceOver 창은 도구가 찾지 못했고, `Ctrl+Alt+Right` 탐색 명령은 `unverified (synthetic_input)`으로 보고됐다. 실제 음성 출력이나 VoiceOver 커서 이동의 증거가 없어 통과로 판정하지 않는다. 점검 후 VoiceOver를 종료해 초기 상태로 복원했다.

실제 로그인·메일 발송·CAPTCHA 해결·공개 후기 작성·계정 삭제는 수행하지 않았다. 이번 범위는 Mac으로 한정했으며 iPhone·모바일 IME·참여자 테스트는 진행하지 않았다. 로컬 데모의 후기 확인창과 계획 변경에 대한 실제 Safari 수동 점검도 남아 있다.

## VoiceOver 재점검 절차

Safari와 VoiceOver를 사용할 수 있는 환경에서 아래를 수행하고 관찰 결과를 기록한다. 테스트 전 켜짐 상태를 기록하고 종료 후 원래 상태로 복원한다.

1. 홈에서 제목·랜드마크 탐색으로 본문과 하단 탐색에 접근한다.
2. 저장 링크를 실행하고 새 제목과 현재 위치가 전달되는지 확인한다.
3. 전시 검색창의 이름, 검색 결과 수, 저장 토글 상태를 확인한다.
4. 내 주말에서 시작 시각·위로/아래로·요일 변경의 이름과 변경 후 위치를 확인한다.
5. 로컬 비로그인 데모에서 후기 별점·본문·요일을 조작하고 취소 확인창을 연다. 제목·설명·버튼 순서, 배경 접근 차단, Escape 후 복귀를 확인한다.
6. 운영 로그인 화면은 입력 이름·동의·개인정보 링크만 관찰한다. 실제 메일 요청·공개 후기·탈퇴는 별도 테스트 계정과 참여자 의사에 따라 수행한다.

|---|---|---|---|---|
| 미실시 | — | — | — | 미검증 |
