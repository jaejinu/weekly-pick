# 위클리픽 사용자 테스트

상태: 과제와 기록 양식 준비 완료. 실제 참여자 테스트는 아직 실시하지 않았다. 예상 결과나 개발자의 점검을 참여자 결과로 기입하지 않는다.

## 진행 준비

- 소요 시간: 약 15–20분. 참여자 1명씩 진행한다.
- 과제 1–4와 선택 후기 과제는 **계정 연결을 끈 독립 로컬 데모**에서 진행한다. 별도 복사본의 `js/config.js`를 `window.WEEKLY_PICK_CONFIG = Object.freeze({});`로 바꾸고 README의 로컬 실행 방법을 따른다. 시작 주소는 `http://localhost:8777/#/home`이다. 실제 iPhone으로 접속할 때는 같은 네트워크의 개발 컴퓨터 주소를 사용한다.
- 과제 5는 https://weekly-pick.vercel.app/#/account 의 계정·개인정보 안내에서 진행한다. 실제 로그인은 필요 없다.
- 운영 사이트에서는 저장·계획 변경에 로그인이 필요하므로 비로그인 상태로 과제 1–4를 진행하지 않는다. 독립 데모를 준비하지 못했다면 해당 과제는 미실시로 남긴다.
- 새 브라우저 프로필 또는 비공개 창을 사용한다. 기기·브라우저·화면 크기를 기록한다.
- 앱에는 처음부터 샘플 저장·일정이 있을 수 있다. 이를 실패나 참여자의 이전 작업으로 간주하지 않는다.
- 기록은 P01 등 익명 ID로 남긴다. 이름·이메일·인증 링크를 수집하지 않는다. 녹화·녹음은 별도 동의를 받은 경우에만 한다.
- 진행자는 성공 경로를 먼저 설명하지 않는다. 2분 이상 막히거나 참여자가 도움을 요청하면 한 번 힌트를 제공하고, 독립 성공과 도움 후 성공을 구분한다.
- 전시·일정은 가상의 데모다. 결제·예매·실제 방문은 하지 않는다.

## 참여자에게 읽어 줄 안내

“이번 주말에 갈 전시를 고르는 웹사이트입니다. 사람을 평가하는 것이 아니라 화면에서 어려운 부분을 찾는 시간이에요. 떠오르는 생각을 말하면서 사용해 주세요. 언제든 중단할 수 있고, 로그인하거나 개인정보를 입력할 필요는 없습니다.”

## 과제

| 번호 | 참여자에게 제시할 상황 | 진행자용 성공 기준 |
|---|---|---|
| 1 | 이번 주말에 가고 싶은 전시 두 곳을 찾아 나중에 다시 볼 수 있게 해 주세요. 이미 저장된 곳을 골라도 괜찮아요. | 두 전시의 저장 상태를 확인하고 저장 목록에서 다시 찾음 |
| 2 | 고른 두 곳을 토요일에 가려고 해요. 일정에 넣고 방문 순서를 바꿔 주세요. | 두 곳이 토요일에 배정되고 순서가 바뀜 |
| 3 | 오후 1시에 출발한다면 몇 시쯤 끝나는지 알려 주세요. | 시작 시각 13:00 선택, 종료 예상 시각을 찾고 말함 |
| 4 | 한 곳은 일요일에 가는 것으로 바꾸고, 다시 토요일로 되돌려 주세요. | 요일 변경과 복귀를 완료함 |
| 5 | 로그인하면 무엇이 저장되고, 후기는 누가 볼 수 있는지 찾아 설명해 주세요. 실제 로그인은 하지 않아도 됩니다. | 계정·개인정보 안내에서 비공개 계획과 공개 후기를 구분함 |

후기 작성·수정·삭제·되돌리기는 **계정 연결을 끈 로컬 데모**에서만 선택 과제로 진행한다. 운영 사이트에 테스트 후기를 게시하지 않는다. 로컬 환경이 없다면 선택 과제는 미실시로 남긴다.

로컬 선택 과제 준비: 별도 로컬 복사본의 `js/config.js`를 `window.WEEKLY_PICK_CONFIG = Object.freeze({});`로 바꾸고 README의 로컬 실행 방법을 따른다. 진행자가 내 주말 하단 데모 날짜를 9.14로 설정한다. 참여자에게 “다녀온 전시의 짧은 후기를 남기고, 내용을 수정한 다음 삭제했다가 되돌려 주세요”라고 요청한다.
