> Beginner MVP V2 고도화 02단계 산출물 · ChatGPT 진단 후 확정

## 2. P0 — 실행 가능한 주말 계획 + 방문 전환

**현재 문제** 내 주말이 관람 시간만 합산한다. 이동 시간·방문 순서·시작 시각이 없어
"11시에 출발하면 5시 전에 끝나는가"에 답하지 못한다. 날짜가 상수 하나로 고정돼
시작 전 전시에 후기를 쓸 수 있고 "다녀옴" 상태 자체가 없다.

**왜 문제인지** V1이 풀려던 "저장만 하고 안 간다"를 마지막 단계에서 해결하지 못한다.

| # | 항목 | 내용 |
|---|---|---|
| P0-1 | 권역 이동 모델 | 대칭 pair **10개** + `getTravelMinutes(a,b)` 단일 조회. 같은 권역도 0분 아님. 교통수단 추정 없이 `예상 이동 25분` 표기 |
| P0-2 | 기사 숫자 제거 | 산문·요약의 하드코딩 시간 삭제 → 전부 `getTravelMinutes()`에서 파생. 잘못된 기존 숫자에 맞춰 행렬을 왜곡하지 않음 |
| P0-3 | 방문 순서 | `plan.sat`/`plan.sun` 배열 순서 = 방문 순서. 변경 시 전체 재계산. 위/아래 버튼 방식 허용(접근성) |
| P0-4 | 첫 시작 시각 | 하루 **첫 시각 하나만** 입력. `10:00~15:00`, 30분 단위. 운영시간 필드는 추가하지 않음 |
| P0-5 | 세로 타임라인 | 카드 사이에 이동 시간 삽입. 시작–종료 시각 표시 |
| P0-6 | 240분 경고 | 기준을 **관람+이동 전체 소요**로 변경. 라벨 `관람 합계`→`전체 소요`. 문구: "반나절을 넘는 일정이에요. 순서를 바꾸거나 한 곳을 덜어보세요." |
| P0-7 | 예약 필수 | **Soft constraint**. 계산에는 포함, 예약 시각 입력 없음, 계산된 시각을 예약 시간이라 표현하지 않음 |
| P0-8 | 날짜 분리 | `issueDate`(2026-09-10 고정) / `currentDate`(데모 상태). `TODAY` 상수 폐기 |
| P0-9 | 발행 vs 현재 상태 | `isIssueEndingSoon`(issueDate) / `runtimeStatus`=upcoming·active·ended(currentDate) / `daysUntilEnd`(currentDate). **ended가 우선** — 종료 임박 배지·D-N 숨김 |
| P0-10 | D-0 처리 | `>0` 종료까지 N일 / `=0` **오늘까지** / `<0` 종료됨. 상세는 "오늘까지예요." |
| P0-11 | 시작 전 | 배지 추가 안 함. 상세에만 "9월 12일 토요일부터 열려요." 저장·계획 **가능**, 방문·후기 **불가** |
| P0-12 | 홈 날짜 대응 | 주말 전 `이번 주말` / 후 `지난 주말`. `이번 주에 끝나요` → **`곧 끝나요`** 영구 변경(정책이 발행일+10일) |
| P0-13 | 방문 완료 | `visited` 상태 신설, `weeklypick.visits` 별도 키. 타임라인(계획된 것) + 전시 상세(종료 전시) 두 진입점 |
| P0-14 | 후기 = 방문 | **`reviewed ⇒ visited`** 강한 불변식. 후기 저장 시 방문 기록 자동 생성. 역은 성립 안 함. `currentDate < start`면 후기 차단 |

### 데모 날짜 프리셋 (임의 Date Picker 없음)

| 프리셋 | 의미 |
|---|---|
| `9.10 목` | 계획하는 날 |
| `9.14 월` | 다녀온 뒤 |

**프리셋 전환 시 실제 변화** (코드로 검증)

| id | 전시 | 9.10 목 | 9.14 월 |
|---|---|---|---|
| `ex-04` | 한지 등불 워크숍 | 시작 전 | **종료됨** (곧 끝나요 레일에서 탈락) |
| `ex-05` | 한남 빈티지 포스터 마켓 | 시작 전 | 진행 중 (오늘까지) |
| `ex-02` | 골목의 기록 | 종료까지 4일 | **오늘까지** |

### 상태 4축 — 서로 섞지 않는 것이 핵심

```
① 발행 상태   isIssueEndingSoon
② 현재 상태   upcoming | active | ended
③ 시간 상태   daysUntilEnd
④ 사용자 상태 saved | planned | visited | reviewed
```

## 3. P1

### P1-1. 후기 수정·삭제 (+ 식별자 체계 변경)

**선행 조건** — 현재 id·order를 배열 길이로 생성해 삭제 시 무너진다.
```
작성 1/2/3 → 2 삭제 → 1/3 → 새 작성 order=3   ← 중복, 최신순 정렬 깨짐
```
→ `nextReviewSeq` 단조 증가값 도입. `id = rv-my-{seq}`, `order = seq`. 재사용·감소 없음.
→ V2 첫 실행 시 기존 localStorage 후기에 seq 재부여 **마이그레이션**.

**규칙** 수정: `visited` 유지, review만 변경 / 삭제: `visited` 유지, review만 삭제.
`mine === true`에만 노출(샘플 6건 제외). 상세에서 삭제 시 → 후기 피드 이동 + `되돌리기` 토스트(저장 해제 패턴 재사용).

### P1-2. 정보 스트립 라벨 정합성
문서는 186px Slider만 축약인데 구현은 `.ex-card` 전체를 숨김 → **186px만 축약, 394px 목록·상세는 라벨 복원**.

### P1-3. Loading / Skeleton 정합성
함수·CSS는 있으나 호출 0회. React 전환 후 **실제 지연 있으면 연결, 없으면 명세 삭제.** 가짜 지연 금지.

### P1-4. 홈 서비스 메시지
`이번 주말, 갈 만한 것만.`이 `<title>`에만 존재. 온보딩 화면 없이 홈 상단에 짧게 노출.
