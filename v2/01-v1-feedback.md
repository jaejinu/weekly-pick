## B. 직접 써보며 남은 아쉬운 점 (V2 후보)

### B-1. 탐색·발견
- **검색 범위가 이번 호 10개뿐**이다. 지난 호 전시는 찾을 수 없다.
- **정렬을 사용자가 바꿀 수 없다.** "종료 임박 순" 고정이라 요금순·소요 시간순으로 보고 싶어도 방법이 없다.
- **필터 상태가 저장되지 않는다.** 다른 화면 갔다 오면 초기화된다.
- 태그가 5개뿐이라 조합해도 결과가 크게 좁혀지지 않는다.

### B-2. 판단
- **핵심 정보 스트립(소요·예약·요금)이 카드에서는 라벨 없이 값만 보인다.** 좁은 폭 때문에 숨겼는데, 처음 보는 사용자는 숫자의 의미를 바로 모를 수 있다.
- 에디터 한 줄이 40자라 "왜 지금"은 전하지만 **근거가 얕다.**
- **다른 사람의 후기가 전시당 1건뿐**이라 판단 재료가 부족하다.

### B-3. 계획 (가장 약한 부분)
- **이동 시간이 계획에 반영되지 않는다.** "이동 시간은 따로 봐야 해요" 문구로 회피했다. 실제로는 이게 반나절 계획의 핵심 변수다.
- **시간대(몇 시에 갈지)를 정할 수 없다.** 토·일 슬롯에 넣기만 할 뿐 순서·시각 개념이 없다.
- **왜 저장했는지 메모를 남길 수 없다.** 며칠 뒤 저장 목록을 보면 이유가 기억나지 않는다.
- 지도가 외부 링크뿐이라 **동선이 얼마나 붙어 있는지 감이 안 온다.**

### B-4. 기록
- **내 후기를 수정·삭제할 수 없다.** 한 번 쓰면 끝이다.
- 종료된 전시는 후기만 가능한데 **거기까지 들어갈 동기가 약하다.**
- 방문 완료 표시가 없어 **"간 곳"과 "갈 곳"이 구분되지 않는다.**

### B-5. 첫인상
- **온보딩이 없다.** "주간 매거진"이라는 서비스 성격을 첫 화면에서 설명하지 않아, 처음 온 사람은 그냥 전시 목록으로 읽을 수 있다.
- **공유 기능이 없다.** 전시나 코스를 친구에게 보낼 수 없다.

## C. 구조적 한계 (V2에서 자연히 해소되는 것)

- 순수 HTML/CSS/JS + 문자열 템플릿 → **V2는 React + TypeScript로 재구현** 예정
- 콘텐츠가 `js/data.js`에 하드코딩 → 새 호 발행 시 파일 직접 편집
- **고정 기준일 상수**(`TODAY = 2026-09-10`)로 D-N·종료 판정 → 실제 날짜 미반영 (시연 재현성을 위한 의도된 선택)
- 이미지 원본이 **4:3**인데 카드가 4:5라 **좌우 40%가 잘린다**

---

## D. V1에서 잘 작동해 유지하고 싶은 것

- **핵심 정보 스트립의 순서 고정**(소요 → 예약 → 요금). 화면이 바뀌어도 같은 자리라 판단이 빠르다.
- **종료된 전시를 지우지 않고 맨 아래로 내리는 규칙.** 아카이브 정체성이 살아난다.
- **저장 직후 토스트에서 바로 "토요일에 넣기"** — 저장과 계획 사이 단계를 하나 줄였다.
- **호수·발행일 구조**가 정적 콘텐츠의 낡음을 자연스럽게 흡수한다.
- **무채색 + 액센트 1색** 원칙. 전시 사진이 화면의 주인공이 된다.
- 빈 상태 문구가 사용자를 탓하지 않고 다음 행동을 알려준다.
