# V2 로컬 구현 기록

2026-10-05. 기존 정적 HTML/CSS/JavaScript 구조에 V2 핵심 동선을 구현했다. 빌드·React 전환 없이 정적 앱으로 구현했다. 2026-10-05 검증된 미리보기 배포를 프로덕션으로 승격했다.

## 디자인 기준

Figma UX 검토 내역을 기준으로 내 주말, 후기 수정·관리, 상세 액션, 빈 상태를 반영했다. 공용 카드·버튼·이미지·Font Awesome 아이콘과 기존 토큰을 재사용한다. 기존 UI 폰트 Pretendard는 유지한다(Figma에서는 대체 폰트 Gothic A1 사용). 홈·기사 전체의 픽셀 단위 재제작은 이번 변경에 포함하지 않는다.

## 구현

- `js/data.js`: 발행일과 데모 날짜 분리. 같은 권역 4쌍+다른 권역 6쌍의 대칭 이동 모델. 권역 기준 데모 예상값이며 교통수단·실제 길찾기 추정이 아니다.
- `js/state.js`: 순서·시작 시각·관람·이동으로 타임라인 계산. 240분 초과 경고. 시작 전/진행/종료 상태. 방문 기록과 후기의 분리. 후기 저장 시 방문 생성, 삭제 시 방문 유지. 샘플 후기 보호. 단조 증가 후기 ID와 V1 마이그레이션. Undo가 다른 항목의 후속 변경을 덮어쓰지 않도록 처리.
- `js/app.js`: 저장 목록에서 요일 지정, 내 주말 순서·시각 조작, 지난 일정의 방문 버튼, 시작 전 상세 계획 진입, 후기 수정·삭제 확인·복구. 검색/저장 빈 상태. 실제 조작에 맞춘 안내 문구.
- `css/components.css`: 44px 공통 컨트롤, 타임라인·예약 안내·방문 상태·후기 관리 스타일. 상세 하단 안내를 고정 바 안으로 배치. 186px 슬라이더만 정보 라벨 축약.
- 호출되지 않던 skeleton 함수와 CSS 제거. 실제 지연이 없는 정적 앱에 가짜 로딩을 넣지 않는다.

데모 날짜 전환은 사용자 흐름 상단에서 제거하고 **내 주말 하단의 접힌 설정**에 배치했다. 기본 날짜는 9.10이며 9.14로 변경하면 종료 상태·오늘까지·방문 전환을 확인할 수 있다. 날짜 변경은 저장·계획·방문 기록을 초기화하지 않는다.

## 저장 데이터

기존 `weeklypick.saved`, `plan`, `reviews`, `recent`의 `{v:1,data:...}` 형식을 유지한다. 추가 키는 `visits`, `dayStartTime`, `currentDate`, `nextReviewSeq`이다.

기존 후기 ID를 `rv-my-{seq}`로 한 번 변환하고 방문 기록을 보완한다. 이후 재실행·삭제·복구에서 ID를 재사용하지 않는다. 기존 저장 목록·계획은 샘플 시안에 맞추기 위해 덮어쓰지 않는다.

## 검증

- `npm test`: 상태 테스트 10개. 대칭 이동, 타임라인 합계/순서/시각, 날짜 상태, 후기 수정·삭제·복구, 샘플 보호, 기존 데이터 마이그레이션, Undo 정합성, 손상/차단 저장소를 검증한다.
- `npm run test:browser`: Chromium에서 요일 지정·순서·시각 변경, 새로고침 유지, 날짜 전환, 후기 작성→수정→삭제→되돌리기, 샘플 보호, 검색/저장 빈 상태를 실제 조작한다. 주요 10개 경로를 360·390·430px에서 확인한다.
- 화면 캡처: `/tmp/weeklypick-v2-qa-{chromium|webkit}` (환경변수 `TEST_ARTIFACT_DIR`로 변경 가능).

외부 폰트·아이콘 CDN은 V1과 동일하게 사용한다. WebKit 엔진 자동 검증과 미리보기 배포 후 확인까지 완료했다. 실제 iPhone Safari와 사용자 대상 사용성 검증은 별도 단계다.

## 미리보기 배포 검증 (2026-10-05)

- 로컬 WebKit: 주요 기능 및 10개 경로 × 360/390/430px 검증 통과. 실제 기기 Safari 검증과는 구분한다.
- 배포본 Chromium: 인증된 테스트 세션으로 같은 시나리오를 검증하여 통과.
- 배포 JS 4개·CSS 3개·이미지 10개: 모두 HTTP 200, 로컬 파일과 바이트 일치.
- 로컬 인증·환경 파일은 `.gitignore`, `.vercelignore`, `.dockerignore`에서 제외한다.
- 이 Preview는 아래 프로덕션 배포로 승격했다.

추가 검증 명령:

```bash
npx playwright install webkit
npm run test:webkit
TEST_BASE_URL=https://your-preview.vercel.app npm run test:browser
```

로그인 보호된 배포의 경우 `TEST_STORAGE_STATE`에 권한 있는 테스트 세션의 Playwright storage state 파일 경로를 전달한다. 인증 파일은 저장소에 넣지 않는다. Vercel 공식 CLI의 `vercel curl`로 인증된 배포 점검을 수행할 수 있다.

## Git 통합 및 후속 UX 점검 (2026-10-05)

- [PR #1](https://github.com/jaejinu/weekly-pick/pull/1)으로 main 병합 및 자동 배포 완료. 상태 테스트와 Chromium·WebKit CI가 PR/main에서 통과했다.
- 초기 수정값을 기준으로 별점·후기·방문 요일·웨이팅의 변경 여부를 비교한다. 변경하지 않거나 원래 값으로 되돌린 수정 화면은 앱 내 뒤로가기/취소 시 불필요한 확인창을 띄우지 않는다.
- 요일이나 웨이팅만 선택한 새 후기도 버리기 전에 확인한다. 계속 작성하면 현재 입력을 유지하며, 수정 취소를 확정해도 저장된 원문은 유지한다.
- 확인창에 설명을 연결하고 배경을 inert 처리한다. Tab/Shift+Tab 순환, Escape 닫기, 호출 버튼으로 포커스 복귀를 검사한다. WebKit에서 클릭한 버튼이 activeElement가 아닐 수 있어 호출 버튼을 직접 전달한다.
- `tests/browser-review.cjs`가 위 시나리오를 두 브라우저 공통 검사에 추가한다.
- 브라우저 자체 뒤로가기·새로고침의 미저장 입력 보호와 실제 iPhone 검증은 이번 보완에 포함하지 않는다.


## 후기 임시 입력 복원 (2026-10-05)

- `js/drafts.js`에서 `weeklypick.reviewDraft.{전시ID}/{후기ID 또는 new}`를 sessionStorage에 보관한다. 같은 탭에서 입력 직후 저장하고 브라우저 뒤로가기·앞으로가기·새로고침 후 폼에 돌아오면 복원 안내를 표시한다.
- 전시·기존 후기별로 분리한다. 등록·앱 내 그만두기·수정 취소 시 임시 입력을 삭제하고, 원래 값으로 모두 되돌린 경우에도 삭제한다. 저장된 후기를 임시 입력으로 자동 덮어쓰지 않는다.
- 기존 후기 원문과 임시 입력의 기준값이 다르면 오래된 초안을 폐기한다. 손상된 저장값은 무시하며 편집 가능한 필드만 복원한다.
- 저장소 차단 시 메모리 내 이동 복원은 유지한다. 새로고침으로 입력이 사라질 수 있음을 화면에 알린다. 탭 종료 이후 복원은 보장하지 않는다.
- 상태·임시 입력 단위 검사 총 15개. 두 브라우저에서 실제 history 뒤로/앞으로 이동, 새로고침, 전시 간 분리, 취소·등록 후 제거를 회귀 검사한다.
- 실제 iPhone 검증은 미완료다. 현재 실행 환경에서 `xcrun devicectl`을 사용할 수 없었다. 자동 WebKit 검사 결과를 실제 기기 결과로 대체하지 않는다.

## 후기 키보드 접근성과 화면 이동 안정화 (2026-10-05)

- 별점 그룹은 Tab으로 한 번 진입하고 선택된 별(미선택 시 첫 별)에 포커스를 둔다. 상하좌우 방향키로 선택과 포커스를 함께 순환한다. [W3C Radio Group 키보드 패턴](https://www.w3.org/WAI/ARIA/apg/patterns/radio/)을 따른다.
- 별점·방문 요일·웨이팅 선택으로 화면이 다시 그려져도 조작한 버튼의 포커스를 유지한다.
- 80자 초과 오류 메시지를 입력창에 항상 연결하여 타이핑 중 오류가 생겨도 설명 관계가 유지된다. 초과 시 등록 차단, 정상 길이 복귀 시 오류 해제를 검증한다.
- 확인창이 열린 상태에서 브라우저 뒤로/앞으로 이동하면 기존 확인창·배경 inert·확인 콜백을 정리한다. 새 화면에 이전 삭제/취소 동작이 남지 않는다. 초안 복원은 유지한다.
- 잘못 인코딩된 해시 쿼리는 무시하여 URIError로 전체 화면이 멈추지 않도록 한다.
- `tests/browser-accessibility.cjs`에서 위 동작을 Chromium·WebKit 공통 시나리오로 검사한다. 키보드 검증이며 실제 스크린리더/실제 iPhone 검증을 의미하지 않는다. 사용자는 iPhone을 보유하지 않아 실제 기기 검증은 보류한다.

## 검색·동네 선택·일정 키보드 조작 (2026-10-05)

- 한글 등 IME 조합 중에는 검색창을 다시 만들지 않고 조합 완료 후 검색한다. 조합 중 input 노드가 교체되는 기존 문제를 먼저 회귀 검사로 재현했다.
- 검색 포커스 URL(`focus=1`)은 진입 시에만 적용한다. 필터·후기 정렬·동네 선택 후 같은 버튼으로 포커스를 돌려주며, 검색어 지우기·추천어·조건 초기화 후에는 검색창으로 돌아간다.
- 동네 링크의 `rg` 값 역시 진입 시에만 적용하여 다른 동네를 선택해도 초기 동네로 되돌아가지 않게 한다.
- 일정 순서 변경으로 현재 버튼이 맨 위/아래에서 비활성화되면 같은 전시의 반대 방향 버튼에 포커스를 둔다. 계속 키보드로 순서를 조정할 수 있다.
- `tests/browser-discovery.cjs`: 합성 composition 이벤트로 조합 중 노드 유지와 최종 검색어 반영, 필터/초기화/동네 링크/정렬의 키보드 조작, 일정 경계의 포커스와 순서 복원을 Chromium·WebKit에서 검증한다. 합성 이벤트는 실제 OS 한글 입력기·모바일 키보드 검증을 대체하지 않는다.

## 화면 이동 접근성 보완 (2026-10-05)

- 키보드로 하단 탐색 링크를 실행했을 때 목적 화면으로 포커스가 이어지지 않는 문제를 회귀 검사로 재현했다. 앱 내 경로 변경 시 대표 제목(없는 화면은 main)으로 포커스를 옮기고, 기존 스크롤 복원을 유지한다. 검색 바로가기는 검색창 포커스를 우선하며 같은 화면의 필터 조작에는 이 이동을 적용하지 않는다.
- 화면별 브라우저 제목을 갱신하고 후기 피드·동네별 보기·지난 호에 보조기술용 h1을 추가했다.
- 검색창 내부에 포커스가 있으면 검색 필드 외곽선을 표시한다.
- 로컬 상태·DB·계정 검사 25개와 Chromium·WebKit의 기존 브라우저 검사가 통과했다. 새 검사는 키보드 화면 이동, 화면 제목·h1, 검색 포커스 표시를 포함한다. 실제 스크린리더·실기기 검증은 별도로 남아 있다.
- 배포 상태는 해당 PR과 Vercel 배포 결과를 기준으로 확인한다. 실제 접근성 확인 범위는 `docs/accessibility-review.md`에 기록한다.

## 모바일 목록 카드 가독성 보완 (2026-10-05, 로컬 검증)

- 목록 카드의 소요·예약·요금 3칸이 좁은 우측 영역 안에서 겹치거나 잘렸다. 화면 전체에는 가로 넘침이 없어 기존 검사에서 놓쳤으며, 카드 내부 경계를 확인하는 검사로 320px에서 실패를 재현했다.
- 목록 카드만 정보를 세로 3줄로 배치해 라벨·예약 조건·가격을 모두 표시한다. 장소·기간도 줄바꿈을 허용한다. 슬라이더·히어로·상세의 정보 배치는 유지한다.
- 주요 10개 경로를 320/360/390/430px에서 검사하고 카드 내부 정보 경계 검사를 추가했다. Chromium·WebKit 모두 통과했다.
- 별도 360px 모바일 터치 에뮬레이션에서 검색 → 저장 → 토요일 배정 → 순서 변경 → 13:00 시작 → 새로고침 유지까지 두 엔진에서 통과했다. 실제 모바일 기기 검증은 아니다.
